# Node.js migration status

The application now uses TypeScript throughout: Next.js frontend, Fastify API, LangGraph JavaScript orchestration, native Firebird Embedded access via prebuilt Koffi, and a TypeScript LLM gateway. No interpreter, ORM, migration runner or provider gateway from the former backend is invoked.

Implemented: Kanban projects/tasks/dependencies/assignments/status/sprint; append-only audit and human approvals; agent registration, profile readiness and per-agent diagnostics; versioned SKILL.md packages; context precedence and project memory; project-scoped agent chat/context summaries; workflow templates/defaults/overrides; durable DAG workflows with parallelism, provider sessions, checkpoints, handoffs, artifacts and human review; isolated workspaces/Git worktrees; file preview/ZIP export; local reviewed merge; optional S3 replication.

Persistence adopts the existing Firebird revision-0011 schema without resetting records. Fresh installs create the equivalent schema from schema.json; node_migrations records adoption. Existing checkpoint rows remain intact. JavaScript checkpoints and writes use a separate nodejs: namespace with typed serialization. New configuration hashes require profile retests and may require fresh runs for unfinished legacy executions.

Validation is deliberately limited per operator preference: backend TypeScript compilation and one integration smoke test. The smoke test covers a fresh real Firebird database, Unicode inserts/updates, profile isolation, append-only audit, actual LangGraph interrupt/approval/checkpoint continuation and a context-summary conversation through a local HTTP contract provider. No cloud inference was invoked. The Windows runtime download was verified against a pinned official SHA-256 and installed independently of the former local environment.

Limits: local single operator; no automatic board pickup, task comments, arbitrary generated shell/tests, deployment executor, production multi-user RBAC, vector search or PostgreSQL adapter. S3, Linux/container execution and live vendor authentication were not validated during this migration. Existing screenshots demonstrate earlier UI features and do not replace validation of this backend.

Final local verification: complete frontend/backend production build passed; the focused smoke passed on Node 24 with the independently downloaded Firebird runtime, including an actual lock conflict returning database_busy/HTTP 409. The running Next.js proxy reports backend=nodejs and Firebird Embedded 5.0.4 with a five-second lock timeout. The original one project, nine tasks and three agents remain. No cloud inference was invoked. An offline pre-launch database copy is kept locally under .data. Execution remains disabled when the enablement variable is unset.
